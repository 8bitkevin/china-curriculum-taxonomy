## 2. Schema 与工具前置变更

1. `curriculum-standards.schema.json`：`stage` 上限 4 → **5**（5 = 高中）；`codeScheme` 说明补 S4/H 编码。
2. `topics.schema.json`：`textbook` 增加可选字段 **`book`**（string，册名，如「必修第一册」）——高中五册需表达册名，而 `volume` 语义保持「学期上/下」与 `semester` 一致（validate 的 `volume===semester` 校验不变）。向后兼容，非 BREAKING。
3. `validate.mjs`：新增轻校验——高中主题（grade ≥ 10）建议带 `book`；`book` 取值仅允许「必修第一册/第二册/选择性必修第一册/第二册/第三册」。
4. 新增 `scripts/apply-batch.mjs`：批次合并工具（读片段 JSON → 合并 topics/edges + 更新 version → 重建 manifest → 跑 validate），消除 19 次重复手工操作。

## 6. 每册工作流（固定循环）

1. 按基线单元结构起草批次片段（topics + edges，含跨册衔接边与理由）
2. `node scripts/apply-batch.mjs <片段文件>`（合并 + manifest + validate）
3. `node scripts/report.mjs` 检查：孤岛 0 / assessmentPrompt 100% / 课标引用 ≥95% / 倒挂边 0
4. commit（约定式：`feat(data): 三年级上册 30 个微主题 + 先修边（M3-1）`）

## 7. 跨学段衔接链专项（M5/M6 退出条件，DEV-PLAN §5）

- 小学→初中：分数→分式、自然数→有理数→实数、小学实验几何（量、拼）→论证几何（证明）、算术解法→方程解法
- 初中→高中：二次函数→幂指对函数→导数、相似比→三角函数、统计表→成对数据回归、概率定性→计数原理量化
- 每册批次落库时显式建边并在理由中注明衔接语义；M5/M6 收尾跑专项抽查（report + 人工核对链完整性）。

## 8. 质量与复核口径（如实声明）

- 机器校验全绿（validate DAG/引用/计数/校验和 + report 四指标）是每册合入的硬门槛；
- CONTRIBUTING 约定的人工复核（每册 ≥20% 通读 + 高风险项全查）**不由本会话替代**：所有批次在 CHANGELOG 标注「机器校验全绿，人工抽读待办」，留待用户按册复核；高风险项（跨学段边、hard 边的教学法正确性）在收尾报告中单独列出。
- 课标 codes-only 不变量不破坏：条目标题为自拟概括，不录课标原文；教材 PDF 不入库（D-004）。

## 9. 会话内执行顺序

课标补齐（1 commit）→ apply-batch 工具（并入课标 commit）→ M3 四册（4 commit）→ M4 四册（4 commit）→ M5 六册（6 commit，含衔接链）→ M6 五册（5 commit，收尾 1.0.0）→ 文档收尾（DEV-PLAN/ROADMAP/CHANGELOG/README/终验，1 commit）。中途任意 commit 点数据集均完整可用（D-008）。
