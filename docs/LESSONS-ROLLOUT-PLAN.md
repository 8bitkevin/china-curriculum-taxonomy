# 知识点学习内容层全库补齐方案（讲解 + 练习）

> 状态：**方案定稿，待执行** · 决策依据：D-031（2026-10-26，修订 D-030 内容来源原则）· 执行方式：Agent 按本文档分批推进，每批一个 commit。
>
> 本文档是执行文档：后续任何 Agent 会话按「§7 每批标准工序」操作即可，不需要重新设计。

## 1. 背景与目标

- 图谱现有 **1641 个知识点**（九科 K12 全学段），每个知识点已带结构化教材映射 `topic.textbook`（人教版 / 年级 / 册 / 单元）。
- 讲解（lessons）目前仅覆盖 **小一数学上册全册 24 点**（D-030 首批，恰好 = 数学 G1上 的全部知识点），其余 **1617 点无讲解**。
- **练习层不存在**：`schema/lessons.schema.json` 无练习字段，viewer 无练习 UI；现有 `examples` 是带解析的示范例题，不是练习。
- 目标：全库 1641 点 **讲解 + 练习双覆盖**；讲解对齐教材（权威、基础），练习教材优先、变式扩展。

各学科知识点数：数学 563（已有 24）、语文 453、英语 249、物理 113、化学 61、生物学 54、历史 54、思想政治 37、道德与法治 35、地理 22。

## 2. 内容原则（D-031，替代 D-030 的「纯原创」条款）

**教材是权威、是基础、是公开知识。内容必须先对齐教材，再扩展加深。**

### 2.1 讲解（lesson）

每个知识点的讲解按四层组织（即现有 `explanation / methods / examples / mistakes` 字段的撰写标准）：

1. **教材对齐层（必须有，核心）**：覆盖对应教材单元的核心知识——定义、法则、术语、标准方法与表述以教材为准。教材怎么定义「方程的解」，讲解就必须讲这个定义，不能另起炉灶。
2. **通俗层**：在教材之上做「为什么、生活场景、直观理解」，让教材知识讲得懂。
3. **方法层**：把教材的方法步骤化、可操作化（口诀、步骤卡）。
4. **易错层**：针对教材要求的常见错误做辨析。

表达规范：用自己的话重述教材知识，**不整段照抄教材原文**；数值、公式、法则、术语、方法名称与教材保持一致。

### 2.2 练习（exercises，新增层）

每点练习按三类题目组合，**教材题优先**：

| kind | 含义 | 占比要求 |
|---|---|---|
| `textbook` | 教材题：教材例题/课堂练习/课后习题的题型与数据保留，题干表述规范化重写 | ≥ 50%（基础层主力） |
| `variant` | 教材题变式：改数值/改情境/换问法，考点同源 | 约 25% |
| `extension` | 扩展加深：超出教材基本要求，通向下一知识点或综合应用 | 约 25% |

数量标准：每个知识点 **≥ 4 题**（小学 1-2 年级可 ≥ 3 题）；难度覆盖 1（基础）/ 2（提高）/ 3（挑战）三档中的至少两档；`textbook` / `variant` 类**必须**带 `source`（册·页·题号，如「人教版一上 P12·练习一 T3」）。

### 2.3 学科特别边界

- **数学 / 物理 / 化学 / 生物 / 历史 / 地理 / 道法 / 思政**：知识点、史实、公式、定理、题型属事实性公开知识，按上述原则对齐采用。图形类题目用文字重述（「一个长 5 厘米宽 3 厘米的长方形」），不嵌图。
- **语文 / 英语**：**课文原文 / 语篇原文一律不收录**（作品版权，承接 D-004 姿态）。讲解对齐教材单元的「语文要素 / 知识点 / 语法体系」，练习采用教材题型 + 自编语料（如：字形辨析、句式变换按教材题型自编句子）。
- **教材 PDF**（D-004 不变）：仅本地 `textbooks/` 参考，不入库、不分发；从 PDF 提取的**单元素材卡属中间工作稿，放 `.scratch/`（gitignore），绝不提交**——素材卡含大段教材原文，入库即违背 D-004。

### 2.4 来源可核对性

- lesson 级新增 `source`：记录对齐的册 / 单元 / 小节 / 页码范围。
- 题级 `source`：`textbook` / `variant` 必填页码与题号，人工可翻书核对。
- 这两个标注是「对齐教材」承诺的可验证形式，validate 强制校验。

## 3. 数据层设计（lessons schema v2）

`schemaVersion: 1 → 2`，全部新增字段可选，向后兼容、渐进覆盖（v1 数据不需迁移即可通过 v2 校验）。

lesson 条目在现有字段（`topicId / summary / explanation / methods / examples / mistakes`）之上新增：

```jsonc
{
  "topicId": "ct_g1a_01",
  // ...现有字段不变...
  "source": {                       // 新增：lesson 级教材对齐标记
    "unit": 1,                      // 教材单元号（= topic.textbook.unit，冗余存储便于核对）
    "sections": ["1.1"],            // 对齐小节（来自 docs/textbook-units）
    "pages": [2, 5],                // 对齐页码范围 [起, 止]
    "alignedAt": "2026-10-26"       // 对齐日期
  },
  "exercises": [                    // 新增：练习题
    {
      "kind": "textbook",           // textbook | variant | extension
      "question": "……",             // 题干（规范重写）
      "options": ["A…", "B…", "C…", "D…"],  // 可选，选择题才有
      "answer": "B",                // 终答（选择给字母；解答题给简短终答）
      "solution": "……",             // 解析（过程）
      "difficulty": 1,              // 1 基础 / 2 提高 / 3 挑战
      "source": { "label": "人教版一上 P12·练习一 T3" }  // textbook/variant 必填
    }
  ]
}
```

validate 新增规则（进 `scripts/validate.mjs` 与测试）：

1. `schemaVersion` 支持 2；`exercises` 若存在则每题 `kind/question/answer/solution/difficulty` 必填；
2. `kind ∈ {textbook, variant, extension}` 时 `source.label` 必填（`extension` 可省）；
3. 有 `exercises` 的条目数量单独统计，manifest 的 `counts` 增加 `lessonExercises` 与 `lessonsAligned`；
4. `source.pages` 若存在须为 `[number, number]` 且起 ≤ 止。

## 4. 教材素材工序（图片型 PDF → 单元素材卡）

教材 PDF 无统一文字层（部分册有、部分是图片版），工序分两轨，产出同一格式的**素材卡**：

```
topic.textbook(册/单元) → docs/textbook-units/{册名}.json(小节→页码)
  → 定位 PDF 页范围 → [轨1] pdftotext 按页提取（有文字层时）
                     → [轨2] pdftoppm 转页图 → Agent 视觉读取（图片册/公式图形补充）
  → .scratch/materials/{册名}-U{单元号}.md 素材卡
```

素材卡固定结构（供撰写时对照，不提交）：

```markdown
# {册名} 第{N}单元素材卡
## 教材核心知识（定义/法则/术语，含小节号与页码）
## 教材方法与例题（题干、解法要点、页·题号）
## 教材练习题清单（课堂练习/课后习题，逐题记录页·题号）
## 本单元覆盖的知识点 ct_id 清单
```

前置工序：**先补索引再写内容**。数学 23 册 PDF 与 23 册单元索引已齐；其他学科需先跑 `python scripts/extract-toc.py`（已有脚本）补 `docs/textbook-units/` 索引（该产物是小节标题+页码的结构化目录，非原文，可入库），每补一批册索引单独 commit。

## 5. viewer 改动（B0 批完成，零构建约束不变）

在现有知识点抽屉内、`mistakes` 易错区之后新增**「练习」区**：

- 每题一张题卡：题号 + kind 徽标（教材题/变式/扩展，用现有学科色系浅色徽标）+ 难度点（1-3 个实心点）+ 题干；选择题渲染 options。
- 交互与抽屉现有展开模式一致：题卡内「查看答案与解析」按钮，点击展开 `answer + solution`；不做作答状态持久化（零构建、无后端，保持仓库定位）。
- 无 `exercises` 的知识点不渲染练习区（渐进覆盖，与讲解缺失态展示一致）。
- `viewer/logic.js` 不新增码表；练习数据直接从 lesson 对象读。

## 6. 分批推进计划

**批次单位 = 一册教材**（一个学科的学期分册）。顺序原则：数学先行（首批样板在小一数学上），小学 → 初中 → 高中；数学完成后按知识点量推进语文 → 英语 → 理化生史 → 道法/思政 → 地理。用户可随时调整后续批次顺序。

| 批次 | 范围 | 点数 | 内容 |
|---|---|---|---|
| **B0 基建** | schema v2 + validate + viewer 练习区 + 小一数学上册 24 点复核 | 24 | 按 D-031 复核既有讲解对齐度、补 `source`、补 `exercises` → 全功能样板 |
| B1–B11 | 数学小学：G1下 → G6下（11 册） | 286 | 讲解 + 练习 |

- 每批一个 commit：`feat(lessons): {学科}{册} 讲解+练习（N 点）— D-031 批次 B{N}`。
- 索引补齐（§4 前置）穿插进行：进入某学科首批前，先一个 `chore(textbook-units): 补{学科}册索引` commit。
- 全程预计 60+ 批；**不设 deadline，质量优先**，每批收尾必须过 §8 验收。

## 7. 每批标准工序（Agent SOP）

任何 Agent 会话执行一个批次（示例：B1 = 数学 G1下）时，严格按以下步骤：

1. **取清单**：`node -e` 过滤 `data/topics.json` 中 `subject==='数学' && grade===1 && semester==='下'`，得到本批 topicId 与 `textbook` 映射；确认 `data/lessons/math.json` 中尚无这些 id。
2. **备索引**：确认 `docs/textbook-units/{册名}.json` 存在且含小节页码；缺则先跑 `python scripts/extract-toc.py` 补齐并独立 commit。
3. **做素材卡**：按 §4 工序产出 `.scratch/materials/{册名}-U{n}.md`（先建 `.scratch/` 并确认其在 .gitignore）。素材卡只做本批单元，不贪多。
4. **逐点撰写**：对照素材卡逐点写 lesson v2——讲解四层（§2.1）、练习 ≥4 题（§2.2，教材题 ≥50%）、lesson `source` 与题级 `source` 逐条标注。术语遵守 D-029（用户可见一律「知识点」）。同一册内口径一致（口诀风格、难度标定参照已有点）。
5. **写入数据**：追加进 `data/lessons/{学科码}.json`（学科码以 `viewer/logic.js` `LESSON_FILE_CODE` 为权威），更新文件头 `lessonCount` 与 `version`（随 topics.json）。
6. **校验**：`npm run validate && npm test` 必须全绿；`npm run manifest` 后 manifest 计数正确（含新增 `lessonExercises`）。
7. **自查**：§8 每批验收清单逐项过；抽查 3 点回翻素材卡核对「教材核心知识已覆盖、教材题标注页码题号真实」。
8. **提交**：清掉 `.scratch/`（或留在本地不入库），commit 信息按 §6 格式；更新本文件 §9 批次台账对应行为 ✅。

## 8. 验收

**每批验收清单**（Agent 自查 + 用户抽查）：

- [ ] `npm run validate`、`npm test` 全绿；manifest 计数一致
- [ ] 本批每个知识点：讲解含教材对齐层核心知识（对照素材卡可核）；练习 ≥4 题（低段 ≥3）且 `textbook` ≥ 50%、页码题号标注真实
- [ ] 语文/英语批次无课文/语篇原文；无整段教材原文照抄
- [ ] viewer 抽屉渲染正常（讲解 + 练习区 + 徽标 + 展开答案）
- [ ] `.scratch/` 未入库；commit 只含 lessons 数据 / 文档台账变更

**最终验收**（全库完成时）：1641 点讲解 + 练习双覆盖；抽 30 点跨学科回翻教材核对对齐度；README/CHANGELOG 更新覆盖率与内容原则（D-031）。
